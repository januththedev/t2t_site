# T2T Guide knowledge

This is retrieval-augmented generation (RAG), not model training. A small free
model receives selected source passages rather than being expected to know T2T.
No embedding service, vector database, or paid model is required.

- `faqs.json`: 50 reviewed question/answer records, with aliases, topic, intent,
  and actual website source paths. Edit these when program facts change.
- `generated.json`: generated by `npm run build`, ignored by git, bundled only
  into the server function. Contains FAQs, section-based website chunks, and
  event listings. It is not copied to the public `dist/` directory.
- `evaluation.json`: regression questions for retrieval, including follow-ups,
  spelling variants, unpublished information, and historical events.

The build reads the current homepage, four main program pages, corporate page,
privacy page, Research Excellence page, and `data/events.json`. It omits scripts,
styles, navigation, forms, archived CRISP pages, and application-success modals.
Add new source pages to `scripts/build-knowledge.mjs`.

Retrieval uses BM25-style lexical scoring, synonym normalization, topic/intent
boosts, prior conversational topic, and current page context. It limits repeated
source sections and supplies at most six compact passages. This is lexical
retrieval, not semantic embedding search. Sinhala/Tamil questions without English
program terms are not reliably retrieved; the interface currently targets English.

Exact reviewed FAQ matches answer without an API call. Unknown/low-confidence
questions abstain. Missing credentials, provider errors, timeouts, and unsupported
model outputs fall back to actual FAQ answers or quoted page excerpts. These
replies are labeled as website information, not AI-generated replies.

Sources come from retrieved records, never model-generated URLs. Prompts instruct
the model to treat evidence/history as data and avoid invented fees or guarantees;
the response filter additionally rejects unsupported LKR/Rs amounts and some false
transaction claims. These checks reduce hallucinations; they cannot prove every
model statement is supported. Visitors should use the linked source pages.

Review FAQs alongside content edits, especially fees, dates, eligibility, and
application links. Source links and published currency amounts are validated at
build time, and missing fee figures fail the build until the FAQ is reviewed. A content hash
identifies each built dataset; it does not assert that old content is current.
Events without a year are not assumed upcoming. The research workshop's full
date comes from its detail page: 2026-03-07. Update that mapping if it changes.

Run `npm test` after content or retrieval edits. Tests run entirely without a
paid API; provider behavior is mocked and live model quality requires a configured
OpenRouter key and a separate live check.
